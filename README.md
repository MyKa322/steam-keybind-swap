# Keybind Swap

Перенос игровых биндов и настроек с одного аккаунта Steam на другой на том же
компьютере. Интерфейс сделан в стиле клиента Steam. Языки: русский, английский,
украинский.

Поддерживаются **Dota 2** и **Counter-Strike 2**.

покажет предупреждение «Неизвестный издатель» — приложение не подписано

репозитория.

Только Windows: приложение обращается к реестру и списку процессов Windows.

## Как пользоваться

1. **Полностью закройте Steam**, включая значок в трее. Это обязательно —
   объяснение ниже.
2. Запустите Keybind Swap. Аккаунты подтянутся сами.
3. Выберите, **откуда** копировать, отметьте **куда** (можно несколько сразу) и
   какие группы настроек переносить.
4. Нажмите **«Показать изменения»** — появится список файлов, а по кнопке
   «Сравнить» видно, какое действие на какой клавише было и какой станет.
5. Нажмите **«Перенести»**. Перед записью автоматически создаётся резервная
   копия, откатить можно в любой момент на вкладке «Резервные копии».
6. Запустите Steam и войдите в целевой аккаунт. Если Steam спросит про конфликт
   облачного сохранения — выберите **загрузку в облако**.

## Почему нельзя просто скопировать файлы

Steam хранит настройки игр в `<Steam>/userdata/<AccountID>/<appid>/`, где
`AccountID = SteamID64 − 76561197960265728`. Рядом с ними лежит
`remotecache.vdf` — манифест Steam Cloud: на каждый файл из `remote/` там
записаны размер, SHA-1 и метки времени.

Если подменить конфиг, не тронув манифест, Steam при следующем запуске увидит
расхождение между записью и файлом на диске и может привести локальную копию к
той, что помнит облако, — то есть **вернуть старые бинды**. Именно поэтому
«скопировал папку — не сработало».

Приложение делает так:

1. Проверяет, что Steam и игра закрыты. Если список процессов получить не
   удалось, перенос блокируется — «не знаю» здесь безопаснее, чем «наверное,
   всё закрыто».
2. Сохраняет резервную копию файлов получателя.
3. Пишет файлы через временный файл и `rename`, затем перечитывает записанное и
   сверяет контрольную сумму.
4. Правит `remotecache.vdf`: обновляет `size`, `sha`, `localtime` и `time`, но
   **оставляет прежним `remotetime`** — так локальная копия выглядит свежее
   облачной, и Steam выгружает её, а не перекачивает поверх.

Точный алгоритм разрешения конфликтов Steam не документирован; логика построена
на разборе структуры манифеста. Если Steam всё же покажет диалог конфликта,
выбирайте загрузку в облако.

## Возможности

- Копирование на несколько аккаунтов за один проход
- Предпросмотр по смыслу: «Атака: `Z` → `Q`», а не построчный diff файла
- Резервная копия перед каждым переносом и откат в один клик. Файлы, изменённые
  уже после переноса, откат не затирает
- Экспорт и импорт набора настроек одним файлом `.d2keys` — можно поделиться
  раскладкой или перенести её на другой компьютер
- Выбор групп: клавиши, настройки игры, группы управления, чат, сетка героев,
  сборки, графика

Файлы, привязанные к личности аккаунта — статистика, история матчей, логотипы
команд, служебные копии Steam `*_lastclouded` — не копируются никогда: они в
deny-листе профиля игры.

## Добавить свою игру

Профиль игры — это один файл в `src/main/games/`. Логику копирования, бэкапов и
манифеста трогать не нужно:

```ts
export const myGameProfile: GameProfile = {
  appId: '730',
  name: 'Counter-Strike 2',
  processNames: ['cs2.exe'],
  groups: [
    {
      id: 'keys',
      labelKey: 'group.cs2.keys',
      descriptionKey: 'group.cs2.keys.desc',
      defaultEnabled: true,
      patterns: ['remote/cs2_user_keys.vcfg', 'local/cfg/cs2_user_keys_0_slot*.vcfg']
    }
  ],
  denyPatterns: [...COMMON_DENY_PATTERNS, 'remote/socache.dt']
}
```

Дальше добавить профиль в `PROFILES` в `src/main/games/registry.ts` и подписи в
три словаря `src/renderer/src/i18n/`. Чтобы узнать реальные имена файлов игры,
загляните в `<Steam>/userdata/<любой аккаунт>/<appid>/`.

## Разработка

```bash
npm install
```

```bash
npm run dev
```

| Команда | Что делает |
| --- | --- |
| `npm test` | Тесты (vitest): парсер VDF, манифест облака, безопасность путей, сквозной перенос |
| `npm run typecheck` | Проверка типов отдельно для main/preload и для renderer |
| `npm run check:steam` | Диагностика на живой установке Steam: что найдено и какой получится план. Ничего не записывает |
| `npm run build` | Сборка бандлов в `out/` |
| `npm run dist` | Установщик `.exe` в `release/` |

Релиз выпускается пушем тега: `git tag v1.0.1 && git push --tags` — GitHub
Actions соберёт установщик и приложит его к релизу.

### Структура

```
src/main/       процесс Node: вся работа с файловой системой
  steam/        поиск Steam, парсер KeyValues, аккаунты, remotecache, процессы
  games/        профили игр и отбор файлов по группам
  transfer/     план, diff, бэкапы, применение
  bundle/       формат .d2keys
src/preload/    мост contextBridge — узкий типизированный API
src/renderer/   интерфейс на React
src/shared/     типы, общие для main и renderer
```

### Замечания по коду

- **Парсер Valve KeyValues свой, не из npm.** Мы переписываем `remotecache.vdf`,
  который читает сам Steam, поэтому важен побайтовый round-trip. Кроме того,
  Valve не экранирует спецсимволы в этих файлах: бинд на клавишу `\` записан как
  `"\"`, и парсер с поддержкой `\"` на нём разваливается. Round-trip проверяется
  тестами на реальных файлах из `test/fixtures/`.
- **`chat.cfg` в Dota 2 — двоичный** (сигнатура `VBKV`), несмотря на расширение.
  Тип файла определяется по содержимому.
- **Формат `.d2keys` — обычный JSON**, а не архив: конфиги малы, зато файл
  остаётся читаемым, и в проекте на одну зависимость меньше. Импортируемый файл
  считается недоверенным: проверяются версия формата, пути (никаких `..` и
  абсолютных), контрольные суммы и размер.
- Renderer работает с `contextIsolation` и без доступа к Node. Все пути
  проверяются на принадлежность папке `userdata/<accountId>/<appid>`.
- Системные утилиты вызываются по полному пути из `System32`, а не по имени из
  `PATH`.
